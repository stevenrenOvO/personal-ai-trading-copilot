# V1.2.1 发布说明

发布版本 `1.2.1`，Git 标签 `v1.2.1`，2026-11-17。在 V1.2 基础上做的稳定性补丁，不改动页面设计和数据格式，可以直接覆盖升级。

## 修复

1. **网络不通时观察池状态不再超时**
   原先逐只串行获取前复权日线，每只最多等 15 秒，10 只最坏要 150 秒，超过页面 90 秒的读取超时。现在所有需要更新的股票并发获取（最多 6 路），单只超时 5 秒，最坏约 10 秒。下载并发进行，写入仍逐只执行。获取失败的股票照旧沿用缓存并注明原因，5 分钟内不再重试。持仓估值同样改为并发获取。

2. **次日早上打开软件也能写入前一天日线**
   原先只认「当前交易日」的收盘快照。收盘后没开软件、第二天开盘前才打开时，缓存里那份前一天的收盘快照被跳过，只能逐只慢慢补。现在会同时检查「应有的最近日线日期」。快照属于哪一天就写入哪一天，仍然只写入已标记为收盘、时间在 15:00 之后的快照。

3. **交易前检查加入涨跌停判断**
   - 按板块计算涨跌停幅度：主板 10%，主板 ST 5%，创业板和科创板 20%，北交所 30%。
   - 盘中：当前封涨停时提示「排队买入很可能无法成交」；买入价高于今日涨停价或低于今日跌停价时，判为不通过。
   - 收盘后：用当天收盘价计算下一交易日的涨跌停价，按它检查计划买入价；当天涨停收盘的，提示下一交易日可能一字板、难以成交。
   - 2026-11-17 实测：长虹美菱涨停收于 4.74，计划以 5.45 买入，判为「高于下一交易日涨停价 5.21，无法成交」。

4. **前端交互测试恢复运行，并覆盖 V1.2 页面**
   - 新增 4 个场景：账户页闭环渲染、交易前检查、记录成交、保存计划。另外补齐测试替身里缺少的 `querySelectorAll`、`URLSearchParams`。
   - 这些测试需要 Node.js。本机没有单独安装 Node 时，可以借用已安装 VS Code 自带的运行时：设置 `ELECTRON_RUN_AS_NODE=1` 后，用 `Code.exe` 代替 `node`。
   - 本次回归：555 passed、2 skipped，跳过的两项是需要显式开启的联网数据测试。

5. **当日日线的来源记录不再被覆盖**
   2026-11-18 开盘前检查时发现：重启或次日早上再次检查收盘快照时，即使没有写入任何新数据，也会把「这一天的日线由哪次快照写入、写入了多少只」这条来源记录改成「写入 0 只」。行情数据本身没有受影响，但审计依据丢失了。现在没有新数据写入时，保留原记录不变；有新数据写入时，作为一次新的写入追加到 `runs` 列表里，并累计 `inserted_total`。旧格式的记录会自动转换成一条写入记录。本机 11-17 那条被覆盖的记录，已按 11-17 当天读取到的原始值恢复，并注明了恢复原因。
