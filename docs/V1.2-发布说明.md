# V1.2 发布说明

发布版本 `1.2`，Git 标签 `v1.2`，2026-11-17。Windows 个人本地运行。

V1.2 把系统从“短线情绪看盘工具”转向“个人波段交易体系的执行与审计工具”。所有新功能集中在「我的账户」页，与 100 万研究用模拟盘相互独立。

## 新功能

### 1. 风控参数文件
- 默认值：账户资金 12,000 元；单笔风险 1%（上限 2%）；单票 ≤20%；首仓 10%–15%；参考止损距离 ≤8%；总仓位上限为趋势向上 50%、震荡 50%、弱势/趋势不明 20%；100 股一手；佣金 0.025%、最低 5 元；印花税 0.05%（卖出）。
- 保存在 `data/personal/risk_profile.json`，可在页面修改，不需要改代码。未保存时页面会注明「当前为默认参数」。
- 「趋势向上」没有单独的规则，默认取震荡上限 50%，可以另行设置。

### 2. 仓位计算器
- 先按止损距离算出可承受亏损，再依次受单票上限、首仓上限、按市场状态的总仓位余量和可用资金限制。按整手计算，并计入最低佣金和印花税。
- 一手都买不起或会超限时，会列出是哪条规则挡住了、一手实际要承担多少风险。不会为了能买而向上取整。

### 3. 观察池（最多 10 只）
- 保存在 `data/personal/watchlist.json`。代码格式为 `600519.SH`，重复添加和超出 10 只都会被拒绝。

### 4. 逐只波段状态
按你给出的规则逐只判断，每个条件都列出数值，可以手算核对：

| 规则 | 实现方式（规则本身没说死的地方做成参数，默认值如下） |
|---|---|
| 周线收盘在向上的 13 周均线之上 | 用**最后一根已收盘的周线**；本周未结束时只作参考显示 |
| 日线 MACD 回零轴附近 | \|DIF\| ≤ 收盘价的 2% |
| 绿柱缩短 | 柱子为负且比前一天短 |
| 金叉放量 | 3 日内 DIF 上穿 DEA，金叉当天成交量 ≥ 前 5 日均量的 1.2 倍 |
| 有效跌破 21 日线离场 | 收盘低于 21 日线 1% 以上，或连续 2 天收在 21 日线下方 |
| 盈利 <15% 按 21 日线；>15% 从最高价回撤 10% 离场 | 以买入后**最高收盘价**判断是否曾达到 15%；达到后改为最高收盘回撤 10% 离场 |

- MACD 采用 A 股常用口径：DIF = EMA12 − EMA26，DEA = EMA9(DIF)，柱 = 2 ×（DIF − DEA）。测试中用独立的 EMA 递推做了核对。
- 状态分为：买点：金叉放量 / 金叉未放量 / 等待金叉 / 周线符合，等待日线信号 / 跌破21日线 / 周线不符合 / 数据不足（日线少于 100 根时）。

### 5. 观察池股票复权
- 均线和 MACD 使用腾讯前复权日线，每只股票每个交易日最多重新获取一次整段序列。前复权在每次除权后会重算全部历史，所以只整段替换，不在旧数据上拼接。
- 当天的复权数据还没发布时，会用本地当日收盘补上，但前提是它的前收盘与复权序列连续。若不连续（可能当天除权），状态停在上一交易日并注明原因。
- 获取失败时沿用缓存并注明，5 分钟内不再重试；没有缓存时退回未复权日线，并提示均线和 MACD 可能失真。
- 持仓期间如果发生除权，成本价按复权系数换算后再算盈利。

### 6. 交易前检查
- 逐项检查：波段规则、是否在观察池、是否在最近一份计划里（不在计划内会提示为计划外交易）、按真实持仓和现金算出的可买手数、按当前市场状态算出的总仓位余量。
- 结果分为「通过 / 有警告 / 不通过」。止损价默认取 21 日线下方 1%；市场状态默认用当天全市场行情快照计算。
- 检查只说明是否符合你自己的规则，不下单，也不构成买卖建议。

### 7. 真实成交与持仓
- 保存在 `data/personal/real_trades.json`，与模拟盘分开。
- 记录只能追加，不能修改；录错时作废并填写原因，原记录保留。系统会拒绝两类操作：卖出超过当时持仓的记录；作废后会导致之后的卖出变成卖空的作废。
- 持仓、成本（含费用，按移动平均）、现金和已实现盈亏全部由记录重新推算。费用默认按费率估算并标注「估算」，也可以填写券商实际收取的金额。
- 每笔记录可以标注是否按计划。

### 8. 收盘后计划
- 按日期保存，新候选最多 3 只（买入价、止损价、股数、条件），持仓逐只给出动作：持有、减仓、离场或加仓。
- 同一天再次保存时，之前的版本保留在 `revisions` 里，复盘时能看到计划是否在事后改过。

## 数据与性能修复
- **收盘快照写入日线**：收盘后用全市场行情快照一次写入当天日线，几秒钟完成。之前需要逐只下载约 5,000 只、耗时数小时。只写入快照标记为收盘、属于当天且时间在 15:00 之后的数据。停牌（零成交量）和价格不自洽的股票不写入，已有的日线不会被覆盖，来源记录在 `ingest_state` 里。2026-11-17 实测写入 5,205 只，与已逐只下载的 1,228 只逐项核对，开高低收和成交量完全一致。
- **日期可分析的标准变严格**：某一天前 20 个交易日（在库内范围内）也都完整，这一天才算「日线可分析」。否则晋级率、炸板率、连板等指标会拿残缺的前一天来算。不满足时，页面标注「行情快照 · 日线待补齐」，市场卡片照常用快照显示。
- **补数据期间页面不再卡死**：后台补数据时，只清除受新数据影响的日期之后的分析缓存，不再整体清空。正在计算的旧日期结果可以正常保存。历史库改为 WAL 模式，读写不再互相阻塞。实测补数据期间，总览首次加载约 54 秒，之后 2–4 秒；修复前一直超时。
- 补数据顺序改为先补指数，再补观察池，最后补其余股票。
- 页面上相同的请求不会重复发送，读取超时从 25 秒放宽到 90 秒。

## 升级说明
- 新数据都在 `data/personal/` 下：`risk_profile.json`、`watchlist.json`、`real_trades.json`、`plans.json`、`adjusted.db`（复权缓存，可删除，会重新获取）。升级时把整个 `data/` 一起备份和迁移即可。
- 历史库 `data/history/market_history.db` 首次运行时会转成 WAL 模式，运行期间会出现 `-wal`、`-shm` 文件。复制数据前请先停止服务。
- 旧的 1.1 服务能读取 WAL 模式的数据库，但不认识 `data/personal/`。

## 已知限制
- 软件关闭期间缺的交易日只能逐只补，补数据时需要保持服务运行，一次性补齐较长缺口需要几个小时。补齐之后，每天收盘后只要软件开着就会自动用快照补上当天日线。
- 冷启动时，全市场结构计算首次需要约 50 秒。
- 本机没有 Node.js 时，前端交互回归会被跳过。本版新增了不依赖 Node 的页面脚本静态检查（重复声明、括号配平、控件与接口连通）。
- 波段规则里「零轴附近」「放量」「有效跌破」的阈值是本版的解释，已作为参数公开。改动需要修改 `BandParams`，页面暂时不能修改。
- 交易前检查与仓位计算只核对你自己的规则，不判断个股基本面，也不保证成交。
