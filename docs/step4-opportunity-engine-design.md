# Step 4 设计：超短线机会引擎（V1.0）

状态：**设计稿，未实现**。等待验收后再进入实现。

目标不是"预测哪只股票会涨"，而是筛选出**当前市场环境下有明确逻辑、明确触发条件、明确失效条件、且可被数据验证**的交易机会。

设计原则：

1. 先判断"现在是什么市场"（Step 3），再判断"现在能做什么类型的机会"。
2. **硬淘汰优先于打分**。不适用的标的直接淘汰，不靠扣分排到后面。
3. **类型分开**。打板 / 半路 / 弱转强 / 分歧转一致 / 首板 / 连板接力 / 低吸 各自有独立的触发与失效条件，不混成一个分数。
4. 排序分可以存在，但必须能拆成 环境 / 板块 / 梯队 / 个股 / 买点 / 风险扣分 六块，逐项可查。
5. 数据能力诚实：没有的能力一律标"未接入"，不用其它指标伪装。
6. 状态机区分"符合条件"与"现在可以买"。

---

## 一、整体架构

```
0. 数据成熟度闸门  →  1. 环境闸门(Step 3 阶段)  →  2. 硬淘汰  →
3. 候选池(Step 2 梯队+板块)  →  4. 类型归类  →  5. 买点状态机  →
6. 可拆解排序  →  7. 风控与仓位  →  输出
```

各层职责：

| 层 | 职责 | 失败时的行为 |
|---|---|---|
| 0 数据成熟度闸门 | 判断当日结构是否已确认、快照是否可用 | 只输出"观察/未接入"，不产生可执行机会 |
| 1 环境闸门 | 由情绪阶段决定允许的机会类型与仓位上限 | 冰点/退潮关闭进攻型；数据不足则不判断 |
| 2 硬淘汰 | 一票否决，不可被分数补偿 | 命中即出池并记录原因 |
| 3 候选池 | 以板块热度 + 板块内梯队为骨架构建 | 板块无热度则不产生候选 |
| 4 类型归类 | 归到 1 个主类型（+1 个次类型） | 无法归类则不输出 |
| 5 买点状态机 | 观察→触发中→可执行→失效 | 触发条件未满足则停留在观察 |
| 6 可拆解排序 | 六块贡献可逐项查 | — |
| 7 风控与仓位 | 阶段上限 × 类型系数 × 单票上限 | 违反即降到观察 |

与现有代码的对应关系：

| 新组件 | 复用 | 新建/重构 |
|---|---|---|
| 数据成熟度闸门 | `HistoryProvider`、`QuoteService` 时鲜元数据、`_history_rows_on` | 新建薄封装 |
| 环境闸门 | `emotion.cycle.classify_cycle` 的 stage/exposure/invalidations | 新建阶段→允许类型表 |
| 硬淘汰 | `board.ladder` 的次新/除权/停牌排除口径、`stock_basic` 行业 | 新建 |
| 候选池 | `LadderSnapshot`（levels/industries/roles/recent）、`sector.engine` | 新建，**替换 20 日突破为主来源** |
| 类型归类 | `OpportunityEngine._classify_role`（空间龙/中军/补涨龙）思路 | 重写 |
| 买点状态机 | `Opportunity.buy_ready`、`invalid_conditions` | 重写 |
| 排序拆解 | `Opportunity.score` | 重写为贡献可拆解 |
| 风控与仓位 | `risk.rules`（MaxPositionWeight/MaxDrawdown/StopLoss）、`paper.engine`、`profile` | 复用 + 类型系数 |
| 回测验证 | `backtest.ashare_engine`（T+1/涨跌停/整手/费用/look-ahead）、`walk_forward` | 复用 + 事件研究模块 |
| 20 日突破 | `strategies.strong_sector_breakout` | **保留为基准策略**，不再作为主机会来源 |

## 二、机会类型

### 2.1 首板

- 识别：收盘 = 涨停价且连板高度 = 1（Step 2），所属板块进入当日热度前列。
- 日线可判的封板形态：无开板（`open==up_limit and low==up_limit`）、开盘后未开板（`open==up_limit and low<up_limit`）、盘中触板回封（`high>=up_limit and low<up_limit and close>=up_limit`）。
- *涨停时间、封单量：未接入。*
- 触发：同板块当日涨停 ≥2 家或板块相对强度 >0 + 个股量能放大 + 收盘封板。
- 失效：板块次日无跟随、个股跌破当日开盘价或涨停结构位。
- 数据：日线足够；盘中确认需分钟数据（V1.1）。

### 2.2 连板接力（2板→3板及更高）

- 识别：高度 ≥2，且属于最强板块的龙头候选/中军候选。
- 触发：梯队完整 + 昨日晋级率 ≥ 阶段基准 + 非高位（V1.0 限 ≤4 板）+ 阶段为发酵/高潮。
- 失效：今日炸板、同板块换龙、晋级率跌破基准、板块跌出热度前列。
- 数据：日线足够。

### 2.3 打板（关键：成交假设）

- 识别：当日涨停且属进攻型结构，板块效应成立。
- **V1.0 保守假设**：
  - 收盘封死（`low==up_limit`）→ 视为**无法成交**，只产生"观察/次日计划"；
  - 当日开过板（`low<up_limit`）→ 按"次日开盘"口径回测；
  - 回测中禁止任何"在涨停价买入"的假设。
- 因此 V1.0 的"打板"= 打板意图 + 次日可执行口径；真正的日内打板属 V1.1（需分钟数据）。
- 失效：开板未回封、尾盘炸板、次日低开超阈值（如 −3%）。

### 2.4 半路

- 识别：板块内已有涨停（板块效应确认），目标股强度靠前但尚未涨停。
- 触发：站上前高、分时放量上攻、回调不破均价线 → **全部依赖分钟数据，V1.1**。
- V1.0：仅标记"半路（需分钟数据，未接入）"，不进入可执行态。

### 2.5 弱转强

- 识别：昨日弱结构（昨日炸板 / 触及涨停未封 / 放量收阴）+ 今日强结构（涨停或强势不回补）。
- 日线可验证的是**结果**：昨日炸板 + 今日涨停。
- V1.0：生成"弱转强已成立（收盘确认）"，买点落在次日开盘（T+1），不假设当日买入。
- 失效：今日未封板、板块未跟随、次日高开低走跌破昨日收盘。

### 2.6 分歧转一致

- 识别：高位股（≥3 板）出现放量分歧日（大振幅/低开拉板/反复开板），次日一致性上板。
- 日线近似：振幅、是否开板、成交额放大倍数刻画"分歧"；"一致"需次日封板确认。
- V1.0：只输出"分歧（观察）"与"一致已确认（次日计划）"，不预测次日是否一致。
- 失效：分歧后次日再炸板 → 结构破坏，淘汰。

### 2.7 低吸（克制使用）

- 识别：已确认龙头/中军，趋势结构完好（未跌破上一涨停日最低价），阶段为发酵/修复。
- 触发：缩量回踩结构位不破。
- 定位：辅助类型，单日上限 1 个，不与同板块高位打板/接力重复。
- 失效：跌破结构位、板块掉出热度前列、阶段转入退潮。

## 三、筛选流程

### 阶段 0：数据成熟度闸门

| 情况 | 处理 |
|---|---|
| 本地历史无该交易日 | 不产生机会，返回"未落地"并给出最近确认交易日 |
| 只有实时快照（当日未收盘） | 只输出观察池，触发条件全部标注"需收盘确认" |
| 快照过期/失败 | 按 `QuoteMeta.is_stale/status` 显式提示，不用旧数据冒充最新 |
| 关键字段缺失（成交额、流通市值） | 该维度标"未接入"，**不参与淘汰与排序**，并在输出中列出 |

### 阶段 1：环境闸门（阶段 → 允许类型）

| 情绪阶段 | 允许的进攻类型 | 仓位上限 | 附加约束 |
|---|---|---|---|
| 冰点 | 无（只观察） | ≤10% | 不产生可执行机会 |
| 退潮 | 无（允许 1 只低吸观察） | ≤10% | 进攻型全部关闭 |
| 修复 | 首板、弱转强、低吸 | ≤30% | 最高板 ≤3 |
| 发酵 | 首板、连板接力、弱转强、分歧转一致 | ≤60% | 主战阶段 |
| 高潮 | 首板、接力（均降级） | ≤50% | 强制标注"不追高"，禁止高位接力 |
| 分化 | 首板、低吸 | ≤30% | 禁止高位接力与打板 |
| 数据不足 | 无 | 0% | 不判断 |

### 阶段 2：硬淘汰 → 阶段 3：候选池

候选池以"当日板块热度 × 板块内梯队"为骨架（不再以 20 日突破为骨架）：

1. 取当日热度前列板块（板块涨停数 ≥2 或相对强度 >0，沿用 `sector.engine`）。
2. 每个板块取：龙头候选、中军候选、补涨候选（Step 2 产出）+ 该板块今日全部涨停股。
3. 补充弱转强候选：昨日炸板/触及涨停未封、今日强势的个股。
4. 每个候选记录：昨日板数、今日板数、昨日是否炸板、量能（缺失标未接入）、板块排名、板块内角色、梯队断层距离。

## 四、硬淘汰规则（一票否决，不可被分数补偿）

### 4.1 标的层

| 规则 | 依据 | 处理 |
|---|---|---|
| ST / *ST | `stock_basic` 名称（用近期波动校正，见 Step 2） | 淘汰 |
| 次新股（上市不足 5 个交易日） | `list_date` + 本地交易日序列 | 淘汰（涨跌幅限制不适用） |
| 除权/送转日 | 涨跌幅超出该板块限制 | 淘汰（基准价不可靠） |
| 当日停牌/无成交 | 当日无 bar | 淘汰 |
| 开盘一字跌停 | 快照 `open == down_limit` | 淘汰 |

### 4.2 板块层

| 规则 | 依据 |
|---|---|
| 与热点板块脱节：板块不在当日热度前列且无相对强度 | `sector.engine` 排名 + 板块涨停数 |
| 孤立板：所在板块当日仅它 1 家涨停且板块相对强度 ≤0 | 板块涨停数 |
| 板块退潮：板块内炸板率 ≥50% 且无回封 | 板块内炸板/回封统计 |

### 4.3 梯队层

| 规则 | 依据 |
|---|---|
| 高位板（≥5）出现在 分化/退潮/冰点 | 阶段 + 高度 |
| 断层上方孤立高度（该高度仅 1 只且断层 ≥2） | `LadderSnapshot.gaps` |
| 同板块已存在更高板且本股非龙头/中军 | 板块内高度分布 |

### 4.4 结构层

| 规则 | 依据 |
|---|---|
| 跌破上一涨停日最低价 | 日线 |
| 连续两日放量滞涨（量能放大 ≥1.5x 而涨幅 ≤1%） | 日线（成交额缺失时用成交量并标注估算） |
| 昨日炸板且今日低开低走（收盘跌幅 >3%） | 日线 |
| 量能极端异常且未封板 | 日线 |

> 命中即出池并给出原因，便于复核。淘汰不允许被其它维度补回来。

## 五、买点状态机

```
观察 ──部分条件满足──▶ 触发中 ──全部条件满足且未过期──▶ 可执行
  ▲                     │                                │
  └──── 条件回落 ───────┘                                │
                       任一失效条件成立 / 时段结束 ──────▶ 失效(带原因与时间)
```

| 状态 | 含义 | V1.0 判定依据 |
|---|---|---|
| 观察 | 在候选池，触发未满足 | 日线结构成立但确认项缺失 |
| 触发中 | 部分成立 | 例：板块转强成立、封板未确认 |
| 可执行 | 全部触发成立、无硬淘汰、在有效时段内 | 收盘确认（次日开盘执行）或快照确认（当日时段） |
| 失效 | 任一失效成立或时段过期 | 记录原因与时间 |

时间窗口（A 股日内阶段，买点不能混为一谈）：

| 时段 | V1.0 可用性 |
|---|---|
| 09:15–09:25 集合竞价 | **未接入**（无逐笔竞价过程） |
| 09:25–09:30 竞价结果 | 仅当快照包含开盘价时可用 |
| 09:30–09:35 开盘五分钟 | 仅 09:35 近似（需分钟数据） |
| 09:35–10:30 主战时段 | 需分钟数据（V1.1） |
| 10:30–14:30 次级时段 | 需分钟数据（V1.1） |
| 14:30–15:00 尾盘 | 尾盘打板风险高，V1.0 不输出可执行 |

**V1.0 的现实结论**：只有延迟快照 + 日线，因此可执行态主要出现在两个时点——T 日收盘后形成次日计划、T+1 开盘后依据快照复核。所有日内触发条件标注"需分钟数据（未接入）"。

## 六、排序逻辑（必须可拆解）

排序分只用于**同类型内部排序**，不决定可执行性（可执行性由状态机决定）。六块贡献全部输出，用户能看到排名靠前的原因。

| 块 | 上限 | 子项（示例） |
|---|---|---|
| 环境适配 | 20 | 阶段是否主战（发酵 20 / 修复 12 / 高潮 10 / 分化 8 / 退潮 2 / 冰点 0）、阶段是否与类型匹配、成交额环境 |
| 板块地位 | 25 | 板块热度排名、板块涨停家数、本股是否板块最高板、板块相对强度、板块是否处于扩散（`diffusion` vs `weakening`） |
| 梯队位置 | 20 | 当前板数是否处于健康高度、板块内梯队是否完整、是否断层孤立、晋级率水平 |
| 个股结构 | 20 | 封板形态（无开板 > 开盘板 > 盘中回封 > 炸板）、昨日结构（首板/接力/弱转强）、量能放大倍数、是否跌破结构位 |
| 买点质量 | 15 | 状态机所处状态（可执行 > 触发中 > 观察）、距离理想买点的位置、是否已高开过多（追高惩罚） |
| 风险扣分 | −30 | 单票仓位、连续亏损、阶段风险、结构破坏风险、流动性未验证、数据缺失项数量 |

输出示例（每行都可点开看贡献）：

```
600xxx  首板  板块：C39电子(第2)  角色：龙头候选  2板
  排序 78.5 = 环境18 + 板块22 + 梯队15 + 个股16 + 买点7.5 − 风险0
  触发：板块涨停≥2 ✓ / 量能≥1.5x ✓ / 收盘封板 ✓ / 次数确认 ✗(需分钟)
  状态：观察（需收盘确认）
```

## 七、风险控制与仓位

1. **总仓位上限** = Stage 3 阶段上限（冰点 10% / 修复 30% / 发酵 60% / 高潮 50% / 分化 30% / 退潮 10%）
2. **类型系数**：首板 0.8、连板接力 0.6、打板 0.5、弱转强 0.7、分歧转一致 0.5、低吸 1.0（相对上限）
3. **单票上限**：`profile.config.max_position_weight`（默认 20%），高阶段不放大
4. **并发上限**：同时持有 ≤3 只，单日新开 ≤2 只（避免同一题材重复下注）
5. **连续亏损降档**：连亏 2 笔 → 仓位 ×0.5；连亏 3 笔 → 只允许观察
6. **止损（T+1 现实）**：买入当日无法卖出，止损只能次日执行 → 明确写出"次日处理"，并记录"隔夜风险"
7. **涨跌停约束**：涨停视为无法成交（见 2.3）；跌停无法卖出 → 回测与模拟盘必须遵守
8. **一手 100 股**：仓位换算向下取整到整手（`paper.engine` 已实现）

## 八、数据依赖

### 8.1 现有数据（足够）

| 数据 | 来源 | 用途 |
|---|---|---|
| 全市场日线 OHLCV（78 个交易日） | 本地 SQLite | 首板/接力/弱转强的历史验证、结构位计算 |
| 推导涨跌停价 + ST 判定（含名称过期校正） | `HistoryProvider.stk_limit` | 涨停/炸板/回封判定 |
| 连板高度、梯队、断层、溢价、晋级率、板块内角色 | Step 2 `LadderSnapshot` | 候选池骨架、排序、硬淘汰 |
| 情绪阶段与切换条件 | Step 3 `classify_cycle` | 环境闸门 |
| 板块强度排名 | `sector.engine` | 板块层硬淘汰与排序 |
| 行业分类、上市日期 | `stock_basic` | 板块归属、次新排除 |
| 当日延迟快照（含时鲜元数据） | `QuoteService` | 当日观察态、开盘溢价假设 |

### 8.2 缺失（必须标"未接入"，不得伪装）

| 缺失 | 影响 | 方案 |
|---|---|---|
| 分钟数据 | 半路买点、开板时点、回封时点、开盘强弱 | 见 8.3 |
| 集合竞价逐笔 | 竞价强弱 | V1.1，若无免费可靠源则长期未接入 |
| 封单量 / 涨停时间 | 封板质量、打板可成交性 | V1.1 |
| 流通市值 / 换手率 / 量比（daily_basic） | 中军识别、流动性淘汰 | V1.1 接入后启用硬淘汰 |
| 财务、股东、龙虎榜、资金流 | 中长线维度（本项目不做） | 不做 |
| 题材/概念板块 | 行业分类 ≠ 题材，跨行业题材会漏 | V1.1 接入概念板块 |
| 已退市/历史股票名单 | 幸存者偏差 | V1.1 |

### 8.3 候选股分钟数据接入方案（设计，V1.1 实施）

- 范围：**只拉候选池**（通常 ≤20 只），不做全市场分钟数据。
- 频率：5 分钟；盘中 09:35 起每 5 分钟增量，收盘后补齐当日。
- 接口：新增 `MinuteProvider.fetch(ts_code, date, freq="5m")`，与日线 provider 同一契约，返回带 `source/as_of/age_seconds/is_stale` 的元数据。
- 缓存：SQLite 落地 + 内存两级（与 `QuoteService` 一致），当日 TTL 300s。
- 用途：开盘强弱近似（09:35）、是否开板、回封时间、前半段成交额占比。
- 明确标注：**09:35 是开盘结果近似，不是真实竞价过程**。

## 九、回测与验证方案

### 9.1 可用历史日线验证

| 可验证 | 方法 |
|---|---|
| 首板/接力的次日表现 | 事件研究：对每个类型的事件，统计 T+1 开盘买入、T+1 收盘/T+2 开盘卖出的收益分布 |
| 晋级率、涨停溢价 | 与 Step 2 直接对齐，可逐日复核 |
| 板块效应 | 板块内涨停 ≥2 与 <2 的次日收益对照 |
| 硬淘汰的有效性 | 淘汰组 vs 保留组的收益分布对照（若淘汰组更强，说明规则选错） |
| 类型分层 | 同高度、同板块热度下的分层对照 |

### 9.2 必须依赖分钟数据（V1.1 才能验证）

半路买点、是否开板、回封时点、开盘强弱、分歧转一致的分时确认。

### 9.3 当前无法回测

- 竞价强弱与竞价买点
- 封单量、涨停时间
- 打板的真实可成交性（只能保守假设"不可成交"）

### 9.4 未来函数与偏差防护

1. 所有特征只用 **T 日收盘及之前**的数据；特征带 `as_of`，执行在 T+1 开盘/收盘（`ashare_engine` 已按此实现并有 `_detect_lookahead`）。
2. **禁止用当日数据预测当日买入**（V1.0 的可执行态只在收盘后/次日）。
3. **幸存者偏差**：本地股票池仅含当前上市股票 → 已知偏差，V1.1 补历史退市名单；在补齐前，回测结论必须标注该偏差。
4. **涨停不可成交假设**：回测中禁止以涨停价成交；开盘一字涨停不得买入。

### 9.5 区分"策略有效"与"恰好选中强势股"

1. **对照组**：同题材、同板块热度、同高度档位的随机抽样股票，比较收益分布（不是只看策略组收益）。
2. **分层条件收益**：按情绪阶段、板块热度、板数分层的条件收益表 —— 如果策略只在发酵期有效，必须明说。
3. **稳健性**：剔除收益最高的 5% 交易后是否仍为正；分半样本（前半段/后半段）是否一致。
4. **样本外**：沿用 `walk_forward`，参数只在训练段确定，在验证/测试段评估。
5. **成本**：手续费、印花税、滑点、开盘溢价假设必须计入。

## 十一、当前设计的潜在逻辑漏洞（自查）

1. **打板在 V1.0 名不副实**：无盘口数据时"打板"退化为"次日跟随"，若不明确标注，用户会以为可以当日打板成交。→ 必须强制标注，且回测禁止涨停价成交。
2. **情绪阶段有 1 日滞后**：阶段由当日收盘结构决定，高潮/退潮往往次日才确认。这是数据决定的，不是 bug，但必须让用户看到"该阶段基于哪一日确认"。
3. **行业分类 ≠ 题材板块**：A 股短线题材常跨行业（如算力横跨电子/计算机/通信），用证监会行业会把同一题材拆散，导致"板块效应"被低估或误判。→ V1.1 接入概念板块前，板块层结论要标注口径。
4. **幸存者偏差**：股票池只有当前上市股票，回测会系统性偏高。
5. **因果循环风险**：用当日涨停结构筛候选，又用同一结构判断次日机会，容易"恰好选中当下强势股"。→ 用对照组与分层条件收益检验，而不是只看策略组收益。
6. **流动性未验证**：成交额在腾讯回补日缺失，无法做流动性硬淘汰，可能选出无法出货的票。→ 缺失时标注"未验证"，不允许静默通过。
7. **硬淘汰阈值是人为选择**（板块涨停数≥2、振幅阈值、量能倍数）：若不做区分度检验，就只是"看起来专业"。→ 用淘汰组 vs 保留组的收益对照来验证阈值。
8. **执行偏移**：V1.0 的信号在收盘后形成，T+1 开盘执行，若开盘已大幅高开，实际收益与回测口径不同。→ 必须内建开盘溢价/滑点假设并单独统计"高开 >3% 的样本"。
9. **类型混仓导致风格漂移**：低吸与打板混在一套仓位规则里，绩效无法归因。→ 按类型分别记录绩效，禁止用打板绩效评价低吸。
10. **数据缺失项的静默效应**：任何"缺失即跳过"的规则都会让策略在缺失日悄悄变形。→ 输出必须列出当日缺失项，缺失比例过高时禁止给出可执行机会。
