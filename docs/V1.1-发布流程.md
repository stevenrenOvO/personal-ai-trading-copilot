# V1.1 本地发布包与交付流程

本流程构建与校验源码 ZIP。构建读取当前工作区已保存的文件，也支持尚未提交的修复和新增文件；不依赖 `git archive`，不执行提交、推送、tag 或远程发布。发布信息和下载附件以[V1.1官方发布页](https://github.com/stevenrenOvO/personal-ai-trading-copilot/releases/tag/v1.1)为准。

## 构建与离线验收

先完成当前版本回归检查并更新 `VERSION`、版本说明、验收清单，再在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/build_release.py --smoke
```

统一发布版本为 `1.1`，输出为 `dist/personal-ai-trading-copilot-1.1.zip` 和同名 `.zip.sha256`。ZIP 根目录为带版本号的项目目录，内含 `RELEASE-MANIFEST.json`，记录每个有效载荷文件的相对路径、字节数和 SHA256。清单本身由 ZIP 外部 SHA256 覆盖；摘要用于检验内容完整性，不代表发布者签名。

`--smoke` 在临时目录解包，以当前Python已安装依赖验证首页与`/health`独立于账户初始化；随后显式启用隔离演示，验证日期、市场、机会、AI和就绪接口有样例数据。全程禁止联网，不启动服务器、实时行情或后台补数。若需确认依赖隔离，应使用全新虚拟环境安装`requirements.lock.txt`后执行此命令。本次已完成该安装与解包检查，见发布验收记录。

```powershell
# 只验证已经构建的包（替换版本号）
.\.venv\Scripts\python.exe scripts/build_release.py --verify dist/personal-ai-trading-copilot-1.1.zip --smoke

# 查看整个 ZIP 摘要，与 .sha256 中的值对照
Get-FileHash dist/personal-ai-trading-copilot-1.1.zip -Algorithm SHA256
```

同一组文件内容在同一 Python / zlib 环境中重复构建，ZIP 字节相同。ZIP 文件时间固定为 1980-01-01，文件权限和成员顺序固定；清单不写入构建时间、本机绝对路径或随机标识。不同压缩库版本可能改变 ZIP 压缩字节，逐文件内容摘要仍可对照。

## 收录范围

打包采用白名单：

- 根目录：README、LICENSE、VERSION、依赖文件、`.env.example`、`.gitignore`，以及启动、停止、安装与演示脚本。
- `backend/` 和现有兼容源码目录：Python 源码；网页静态目录只收录明确允许的 HTML、CSS、JavaScript、图片与字体。
- `scripts/`：Python / PowerShell / CMD 工具。
- `docs/`：Markdown / Python 文档工具，以及明确允许的 `V1.1-research-report.json`。
- `tests/`：Python / CJS 测试；CSV 仅收录 `tests/fixtures/` 下明确指定的四个公开样例文件，演示界面会标记为测试数据。

整个真实 `data/` 目录、`.env` 及其变体、`.git`、`.venv`、日志、PID、运行状态、数据库、缓存、临时目录、账户和行情快照都不进入包。`backend/data/*.py` 是数据层源码，正常收录。链接 / Windows junction 位于收录目录中会直接报错，避免读取项目外部文件；源码内若有人直接写入私密内容，发布前仍需代码审查。

验证器在解包前拒绝路径穿越、绝对路径、Windows 备用数据流、保留设备名、大小写重复路径、链接成员、清单外文件和内容摘要不符。加入未批准的新资源扩展名或新 fixture 需要先修改脚本白名单并补充验证。

## 本地交付与升级验收

1. 将 ZIP 解压到新目录，保留旧版本目录作为回退依据。
2. 按包内 README 安装依赖，先以演示模式检查页面和基础操作；真实行情接入后的空数据、补数进度也要单独检查。
3. 停止旧服务后备份原 `.env` 和完整 `data/`；将需要沿用的配置及数据拷贝到新目录。勿让两个进程同时使用同一份模拟账户。
4. 启动新版，确认 `/health` 版本、`/ready` 状态、最近完整日线日期、账户余额及成交记录，再按照 `V1.1-验收清单.md` 验收。
5. 若需回退，停止新版并恢复旧目录及升级前数据备份。新版本账户字段不应直接交给更早格式的服务处理。

远程 `v1.1` tag / Release与本地ZIP构建分别执行；应将已验证的源码保存到同一Git提交，确保标签、ZIP及SHA256一致。构建脚本不包含远程操作；发布信息以官方发布页为准。对外部署属于独立工作，本版提供Windows个人本地体验。
