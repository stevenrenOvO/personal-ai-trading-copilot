# V1.1 数据显示修复

日期：2026-10-23。针对用户反馈“数据都没显示”的开发期修复记录，统一纳入发布版本 `1.1`。下列日期、测试与页面结果保留当时的基线，不表示更名后重新验收；当前发布材料见 `V1.1-发布说明.md` 与 `V1.1-发布验收记录.md`。

## 已复现的原因

1. 盘前将当前交易日直接设为网页默认日，此时当天尚未开盘；昨日全市场快照被限定为只能用于当前日，无法显示。
2. 日期列表只判断是否有数据，没有标记覆盖率；20/21 等日期只有约六成股票时仍可作为普通日期选择。
3. 部分接口标记正常但没有数据，另一些回退到更早日期；历史回退计划仍返回可进攻。
4. 整个补数任务结束才清缓存；少数停牌/新股无数据的旧任务反复占用队列，指数又不在自动补数股票名单中。
5. 连板算法可能跳过整个缺失开市日，将不相邻的交易日连在一起。

## 修复后的行为

- 默认选择最近覆盖充分的历史日，真实当前交易日单独用于模拟单；按钮可切换最近日线和最近行情快照。
- 按股票名单交集、有效 OHLC 和覆盖率标记可分析日期；指数不计入股票覆盖。不足的历史日期显示覆盖率并禁选，有足量快照的日期仍可查看快照。
- 各模块展示自身实际日期；缺日数据返回明确状态，无默认评分/仓位；历史回退计划禁用进攻和新仓数量。
- 昨日收盘快照在次日盘前保持收盘状态；市场页从同日已确认日线补充连板、溢价和指数指标。
- 最新缺口优先补数；高覆盖率的少量缺失降为低优先级、6小时退避；增加核心指数补数，每只下载更新进度，有新数据时每5秒失效缓存。
- 合并本地真实开闭市日历，缺失开市日中断连板；修正上市日恰等于本地窗口首日的次新判断。
- 前端刷新跟进新补齐日期，手动选历史日期时保留选择；新增真实首屏内容检查。

“可分析/完整”表示有效股票覆盖达到90%门槛，并非所有证券都有每日 bar；剩余停牌、新股、供应商缺失会继续展示和重试。分钟、竞价、封单等未接入字段仍会明确标注。

## 接口调整

`GET /data/latest` 的 `date` 为默认展示日；`current_trading_day` 为真实当前交易日，交易客户端应使用该字段。另提供 `latest_complete_date`、`snapshot_date`、`display_reason` 和逐日 `history_dates`（含覆盖率、是否可分析、是否有快照）。

`GET /data/ingest/status` 的 `progress` 展示窗口、已处理/总数、更新、失败及更新时间；`/ready` 同时透传进度。
